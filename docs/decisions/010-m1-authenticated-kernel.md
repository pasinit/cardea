# ADR-010 — M1 Authenticated Headless Kernel

Date: 2026-09-23. Owner: kernel/runtime. Scope: finish M1; R01–R05, bounded R06, M1 R08/R12.

**Status: implemented and verified. M1 is complete for the bounded authenticated headless profile; M2 confinement and later agent capabilities remain open.**

## Requirements and Decisions Before Implementation

Deliver an authenticated Unix-socket service and structured client with persisted principals, exact external bindings, accountable supervisors, immutable task provenance, explicit grants, deterministic execution and restart recovery. Preserve v0.1 records/digests. Every new effect must satisfy the live supervisor permission/delegation ceiling, ancestor ceilings, task grants and platform policy. The service exposes no arbitrary processes, model calls or external effects in M1.

Reuse the decisions and executed fit evidence in ADR-001 and ADR-007–009: SPIFFE Workload API validation, Authlib/OIDC, FastAPI/Pydantic/Uvicorn/HTTPX, versioned RFC 8785 request identities, DBOS 3.0.0 queues/history/datasources and shared SQLite transactions. Native `DBOSClient.send_in_transaction` also permits journal events and durable wake messages to share the admission database. Do not add another dispatcher, credential issuer or event outbox.

| Remaining choice | Candidates and selected composition |
|---|---|
| Policy evaluation | Evaluate Casbin 1.43.0 (Apache-2.0, maintained Python implementation) for exact subject/namespace/action policies, expiry and delegation, loaded from the current SQLite transaction. OPA supports richer Rego policies but adds a service/process or runtime boundary; OpenFGA supports relationship intersections but adds a separately persisted/service decision boundary. Neither is rejected generally. For M1's small local profile select Casbin if live-ceiling and denial tests pass. The adapter resolves ancestor/provenance data and intersects decisions; it is not a new policy language. |
| Migration | Reuse Alembic with an explicit service version table and caller-owned SQLAlchemy transaction. Keep v0.1 `user_version`, snapshots and hashes unchanged. DBOS retains ownership of its native migrations. Compare hand-written migration bookkeeping: no gap justifies replacing Alembic. Back up the whole file using SQLite's backup API before coordinated upgrades. |
| Human authentication | Reuse Authlib authorization-code + PKCE login, OIDC discovery/signature/nonce validation, and RFC 7662 access-token introspection. Validate against pinned Keycloak 26.7.4 in disposable development state. Provision exact `(issuer, subject)` mappings. ID tokens never authenticate API calls; provider endpoints and audience are configured, never supplied by token claims. A custom login/issuer is unnecessary. |
| Ownership/operations | POSIX advisory service lock permits one DBOS executor per private store, including startup migration and restore. Stable executor identity is reused only after the old process releases the lock/dies. SQLite backup and explicit stopped-service restore cover the complete shared database. No distributed failover claim. |
| Client/wire | Explicit `/v0.2` endpoints, strict bounded models, typed sanitized errors, body/response bounds and HTTPX Unix transport. A Python client plus exported OpenAPI covers M1; legacy demo routes remain separate. |

Internal task references use standard UUIDv4 (Python `uuid`) with a resource prefix; the persisted unique `(supervisor, request_id)` binding supplies retry identity. There is no need for a custom deterministic identifier scheme. Policies are explicit exact namespaces/actions; there are no wildcard roles or administrator bypass in the agent API. Task admission derives the supervisor from the authenticated caller. Grant creation is part of that admission and rejects broader scopes. Trusted host administration provisions identities and current policy, with transactional audit and wakeups on policy changes. It does not rewrite task provenance. Old trusted tasks lacking provenance remain inaccessible through the authenticated API.

The first runtime performs only bounded JSON artifact publication and independent deterministic verification. Its DBOS datasource commits the existing Cardea operation receipt, artifact, checkpoint and native saved result together. Native durable messages/timers advance explicit waits; terminal Cardea states do not reopen. Each newly executed phase rechecks live authority under the write transaction. Cancellation/revocation cannot retroactively undo committed artifacts, but block subsequent work. Retain history; no automatic pruning before a separately tested retention policy.

## Acceptance Gate (Passed)

- Migrate a populated v0.1 store without changing its records/receipts; fail safely on unknown versions and interrupted upgrades; restore a consistent shared-store backup.
- Real SPIRE and OIDC/Keycloak proof checks, rotation/provider failure, exact principal mapping, persistent disablement and authenticated supervisor provenance.
- Real Unix-socket submit/inspect/cancel/client flow, strict versions/types/limits, sanitized errors, wrong-principal and forged-body denials.
- DBOS atomic admission/enqueue and journal/wakeup; kill/restart at checkpoint and commit boundaries; acknowledged artifacts/receipts preserved; one executor; deadline/cancel/terminal invariants; independent artifact verification.
- Live supervisor permission/delegation, explicit grant, ancestor and platform denials at admission and new dispatch/retry/resume. Broader service credentials/approvers cannot override ceilings; new supervisor rights do not expand old grants.
- Root regressions plus reproducible deterministic headless acceptance, with Debian evidence reported separately from M2 confinement. No UI/model dependency.

Primary sources: [Casbin model/policy](https://casbin.apache.org/docs/overview/), [PyCasbin](https://github.com/casbin/pycasbin), [OPA](https://www.openpolicyagent.org/docs/policy-language), [OpenFGA intersections](https://openfga.dev/docs/modeling/agents/task-based-authorization), [Alembic](https://alembic.sqlalchemy.org/en/latest/cookbook.html), [Keycloak](https://www.keycloak.org/securing-apps/oidc-layers), [Authlib HTTPX integration](https://docs.authlib.org/en/latest/client/httpx.html), [OAuth introspection](https://www.rfc-editor.org/rfc/rfc7662), [PKCE](https://www.rfc-editor.org/rfc/rfc7636), [DBOS transactional client](https://docs.dbos.dev/python/reference/client). Exact release/license/maintenance/build inventory and executed results will accompany completion; no transitive security certification is implied.

Revisit the composition if policy snapshots cannot remain ordered with effects, DBOS upgrade/ownership semantics break shared persistence, or measured supported-host constraints require another provider/engine. M2 still owns full resource policies, process-tree confinement and real tool execution; M3 owns model execution and external input ingestion.

## Implemented Scope and Measured Results

The implementation lives separately in `apps/api/src/cardea/service`; the v0.1 kernel and ADR-008/009 experiment source hashes remain unchanged. [Quickstart](../m1-quickstart.md) describes provisioning, workload/human clients, backup/restore and explicit limits. [Reproduction](../../experiments/m1/README.md) and [machine-readable evidence](../../experiments/m1/evidence/summary.json) bind individual case outcomes to sources and dependency/build versions.

- **46 real-provider service cases pass on each supported M1 test profile:** native macOS arm64 and Debian 13 amd64 in Docker on the same host (emulated amd64). SPIRE, Keycloak, the Unix-socket daemon, DBOS and SQLite are real processes/libraries, not mocked identity or scheduler services.
- **144 backend and 4 frontend regressions pass**, including six portable service migration/contract checks. Root lint/type checks pass. The authenticated demonstration and exported OpenAPI are checked separately.
- The eight before/after commit crashes cover admission/enqueue, artifact/receipt/checkpoint/native result, terminal verification/native result and event/wakeup publication. Acknowledged state survives; retries do not create duplicate tasks or artifacts.
- Live policy tests deny broader admission, delegation withdrawal, platform restrictions, ancestor amplification, disabled supervisor/agent/runtime, expiry and revocation before dispatch, privileged outsider access and resumed work after revocation. Current checks occur inside the same serialized transaction as each new effect. Cached native results never authorize the next phase.
- Real OIDC tests cover code+PKCE login, issuer/audience/signature/nonce checks, refresh, persistent human supervisor identity, local disablement, wrong audience, unavailable introspection and ID-token rejection. Real SPIRE validates current workload proof and fails closed on agent RPC outage; ADR-009 preserves the independent bootstrap/rotation/expiry evidence.
- Alembic preserves a populated v0.1 store byte-for-byte at the row level, adds no invented provenance, rolls back an injected migration failure and rejects unknown revisions. Stopped-service backup/restore preserves DBOS waits and receipts. Private paths and exclusive ownership are tested.

**Fit-driven changes.** Keycloak 26.6.2+ requires the introspecting client in the access-token audience; the fixture/configuration uses the kernel client as its intended audience, retaining the provider check ([upstream migration guidance](https://www.keycloak.org/docs/26.7.2/upgrading/)). DBOS 3.0.0's synchronous executor shutdown uses `shutdown(wait=False)` and does not join active workflows. The daemon is therefore a dedicated process: Uvicorn drains HTTP, and the owner lock remains held until native process termination. An ordinary return after closing DBOS must not release the lock to surviving workers. SIGTERM and hard-kill recovery both pass. This is the smallest process-ownership adapter; no replacement queue, credential issuer or background scheduler was built.

**Version/license/maintenance evidence.** DBOS 3.0.0, Alembic 1.20.0, SQLAlchemy, FastAPI and Pydantic use MIT; Casbin 1.43.0, SPIRE 1.15.3, py-spiffe 0.3.1, Keycloak 26.7.4 and rfc8785 use Apache-2.0; Authlib 1.8.0, joserfc, HTTPX and Uvicorn use BSD-3-Clause. The installed Python inventory records exact versions and license files. The new policy/migration choices have maintained non-archived upstreams, with release/upload observations recorded in evidence; prior decisions supply the engine/provider comparisons. Authlib emits an upstream HTTPX deprecation warning under the tested lock. This direct-composition review is not a full transitive vulnerability certification.

**Boundaries retained.** M1 has one fixed, trusted transactional JSON runtime, four workflow slots, 100 active-task admission capacity, bounded payloads and absolute deadlines. Waits occupy workflow slots. Policy/identity failure prevents new effects and terminates affected work; an old committed artifact is not retroactively erased. Local principal disablement is distinct from provider credential validity. Same-UID workload sharing remains a host boundary, not logical-agent isolation. All history is retained and disk capacity must be monitored. No multi-host takeover, external effect recovery, general agent delegation/budget sharing, model execution, input watcher, arbitrary host tool, worker confinement, automatic provider installation, Debian package or reboot acceptance is claimed.

**Gate disposition.** M1's R01–R05 and R08/R12 portions are verified for this profile. Casbin's bounded R06 selection enforces the mandatory ceiling now; broader M2 authorization and R07 confinement remain open. Later M3–M5 decisions and acceptance requirements are unchanged.
