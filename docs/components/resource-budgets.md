# Resource Budgets

**Reuse decision.** [ADR-015](../decisions/015-m2-accounting-retention-and-acceptance.md) composes SQLite/SQLAlchemy transactions, Alembic migrations and systemd measurements. Windowed rate-limit counters cannot join the existing receipt transaction or preserve uncertain consumption. Cardea adds only allocation/reservation records for that gap. See [R09](../standards-review-2026-09-22.md#r09--runtime-and-budgets--m2m3).

**Purpose.** Reserve capacity before host effects and account for observed or conservatively unknown consumption.

**Design.** Each installed host task retains fixed limits: 10,000 tool milliseconds, 65,536 worker-output bytes and one effect. Host-owner `host_budgets` additionally bound cumulative consumption and concurrent operations per authenticated supervisor and namespace. Admission checks capacity; the intent transaction reserves the full maximum before launch. SQLite writer serialization prevents competing dispatches from spending the same capacity. Missing allocations deny execution. Reprovisioning changes limits without resetting consumption.

**Settlement.** Systemd monotonic execution timestamps measure worker elapsed milliseconds; bounded stdout/stderr length measures output bytes. Receipt/verification/result and settlement commit together. Known measurements release unused reservation; missing measurements or interrupted effects retain the full maximum. Settlement is idempotent. CPU/memory observations remain supplementary; tool time is worker execution duration, not API latency or an invoice. Output accounting covers worker stdout/stderr, not all database/receipt storage.

**Authority and recovery.** Live authority and allocation reductions are checked at dispatch, monitoring and publication. The durable reservation survives a daemon crash. Unknown effects are never automatically repeated. Alembic imports historical host receipts conservatively. M5 snapshot restore migrates private staging and seals historical execution scopes, including those absent from the snapshot. Fresh authority and budgets are required in the reported recovery namespace; increasing old allocations cannot bypass this fence. Current-store reboot recovery retains conservative accounting. See [operations](../operations.md).

**Inspection.** Authenticated `GET /v0.2/host-budget?namespace=...` reports the caller's limits, total charged/reserved amounts, active reservations and terminal cleanup backlog. Omitted allocations deny new work; the host owner may explicitly increase cumulative limits.

**Status.** M2 host accounting is implemented with concurrency, exhaustion, settlement, migration/restore and failure tests. Model/provider accounting is implemented for the bounded M3 profile below; live GLM-4.7 usage is verified. ADR-017 adds one-level child sharing for the installed M4 coordinator. Each immutable slot reserves 10,000 tool milliseconds, 65,536 output bytes and one step from the parent; the parent also reserves one step and 32,768 bytes for publication. Slots are not recycled. Dispatch enforces the parent concurrency ceiling and the existing supervisor host pool. Model calls/tokens are zero for this profile; delegated model work is unsupported.

**M3 extension.** [ADR-016](../decisions/016-m3-openrouter-and-native-mcp.md) implements cumulative model call/token allocations per supervisor and namespace. Each model intent atomically reserves one call and 32,768 input tokens plus its output cap; valid reported usage settles the reservation, unknown usage retains it, and observed overage is retained without permitting further execution. This conservative token reserve is not an invoice guarantee. M3 tools share the existing host pool. `GET /v0.2/model-budget` reports model allocations/usage. Portable concurrency, exhaustion, revocation and migration tests pass; live GLM-4.7 acceptance records 1,541 tokens and reported cost across two successful calls. Unknown receipts describe recovery outcomes; the durable budget ledger remains authoritative for conservative charges, including after lease-expiry recovery.
