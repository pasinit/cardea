# Tasks and Scheduler

**Reuse decision.** Compare maintained schedulers and durable workflow engines with the existing store against lease, wait, cancellation, and uncertain-effect tests before writing a dispatcher. [ADR-002](../decisions/002-workflow-engine-comparison.md) records a 17-project comparison and four-candidate shortlist. [ADR-003](../decisions/003-dbos-fit.md) records the first isolated DBOS results and integration gaps; [ADR-004](../decisions/004-temporal-fit.md) adds the Temporal comparison. [ADR-005](../decisions/005-absurd-fit.md) adds Absurd results and event/child/retry mapping requirements. [ADR-006](../decisions/006-hatchet-fit.md) adds Hatchet observations. [ADR-007](../decisions/007-runtime-integration-direction.md) selects DBOS for integration. [ADR-008](../decisions/008-dbos-storage-integration.md) verifies native transactional admission/publication against Cardea storage and explicit takeover with stale-broker denial; production integration and coordinated migration follow in [ADR-010](../decisions/010-m1-authenticated-kernel.md). See [R05](../standards-review-2026-09-22.md#r05--scheduler-and-recovery--m1).

**Purpose.** Advance durable logical tasks independently of a browser or individual worker process.

**Design.** Persist queued, running, waiting, suspended, and terminal states. The verified experiment assigns queue/history progression to DBOS and maps the existing bounded lease to broker/storage guards. Carry this single-dispatcher ownership into production integration. The bounded M1 profile admits up to 100 active tasks with four concurrent DBOS workflows; waits occupy workflow slots. Every mutation checks the expected revision and current lease. Checkpoints save explicit progress, object versions, and event cursors; terminal success requires verification evidence.

**Authority.** Persist the accountable supervisor and delegation provenance. Admission, retry, and resume must re-evaluate current supervisor/ancestor permissions; stored checkpoints and old receipts never restore revoked authority.

**Boundary and recovery.** Commit state and journal events together. After lease expiry, cancel undispatched intents and classify unfinished dispatched effects as uncertain. Requeue only safe work; unresolved effects fail the task pending reconciliation. Terminal tasks remain terminal. Cancellation coordinates with the host adapter to stop descendants; checkpoints do not restore process memory.

**Acceptance.** Competing claims cannot acquire the same revision; a restarted worker resumes acknowledged progress without replaying an uncertain effect.

**Status.** Lifecycle and storage checks exist in [lifecycle.py](../../apps/api/src/cardea/kernel/lifecycle.py) and [store.py](../../apps/api/src/cardea/kernel/store.py). The authenticated service now runs continuous DBOS dispatch, transactional event wakes and deterministic verification, with exclusive process ownership and tested restart recovery. M2 adds real confined worker process-tree cancellation and reconciliation. M4 reuses DBOS control wakeups with a separate two-slot coordinator queue; four worker slots remain available, and committed child associations supply recovery progress. Automatic multi-host failover remains unsupported.
