# Installed Host Operations

**Purpose and reuse.** Run fixed operations under live authority on the persistent Debian host, with verified results and durable receipts. [ADR-015](../decisions/015-m2-accounting-retention-and-acceptance.md) completes the registry/accounting/retention composition built in ADR-012–014.

**Registry and API.** `host.sha256` returns SHA-256 and byte count; `host.copy` returns base64 bytes and byte count. Both accept declared JSON through `/v0.2/host-tasks` (`HostTaskRequest`, `submit_host`, CLI `submit-host`) or one immutable stored version through `/v0.2/host-object-tasks` (`HostObjectTaskRequest`, `submit_host_object`, CLI `submit-host-object`). Stored-input requests have an empty reserved `payload`. Discovery supplies permitted installed entries, input modes, scope, limits and retry behavior. No caller code, command, path, mount or verifier is accepted.

**Scopes and authority.** The exact operation grant, current supervisor allow/delegate, platform policy and task namespace object rights must all hold. Stored input additionally requires source-namespace and exact namespace/object/version/digest read grants. Check admission, dispatch, monitoring and publication; the earliest required permission expiry bounds the worker deadline. Output names are fixed to the task in its authorized destination namespace. Root tasks support inline or exact-version object input. ADR-017 additionally allows bounded inline hash/copy children through authenticated, allocated M4 delegation; arbitrary child admission remains rejected. A successful exit alone never proves completion: the kernel independently verifies output bytes/digest and commits result, evidence, receipt and success together.

**Host boundary.** The unprivileged kernel account invokes one fixed root-owned sudo helper. Separate worker accounts and systemd/bubblewrap enforce namespaces, read-only declared inputs, private bounded scratch, denied network access, no capabilities, 64 MiB memory, 8 processes, 50% CPU, 8-second execution and 1-second stop timeout. Inputs are at most 16 KiB and combined output at most 64 KiB. Service data/credentials stay outside worker mounts. Missing facilities, different pinned versions or a mismatched helper digest reject dispatch. The kernel account is trusted infrastructure.

**Accounting and recovery.** [Host allocations](resource-budgets.md) reserve 10,000 ms / 65,536 bytes before dispatch, settle measured usage where available and charge the full bound when unknown. A durable intent and exclusive job identity prevent automatic re-execution. Policy updates serialize against final dispatch. Monitoring polls live authority with 100 ms between polls, plus bounded provider/helper latency. Host limits remain active during daemon outages; lease recovery terminalizes unresolved tasks within the existing 40-second claim bound. Cancellation requires confirmed process-tree stop. M5 verifies interrupted effects across a full-machine reboot, retaining `outcome_unknown` and host tombstones. Snapshot restore seals old execution scopes; see [operations](../operations.md).

**Retention.** After a terminal receipt commits, cleanup confirms the unit/cgroup is stopped, persists a root-helper SQLite tombstone and removes that job's input/output directory. Completion and five-second startup/periodic maintenance retry pending cleanup; a lost acknowledgment is safe. Unknown receipts remain unknown even after their payload is retired. The 256-directory cap remains fail-closed during cleanup failures. Compact replay tombstones and kernel audit history are retained indefinitely; never remove the helper history to free capacity. `host-budget` reports terminal cleanup backlog. No secure-erasure guarantee is made. Already committed output remains governed by task access policy after source revocation.
